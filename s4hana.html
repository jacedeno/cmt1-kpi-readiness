S/4HANA: how the Planner and the KPIs carry over

SAP S/4HANA is planned for December 2026. This page shows, screen by screen, what the tool does today on SAP ECC, what can move back into SAP if the new system provides it, and what stays in the tool otherwise; then the few questions the answer depends on.

Screen by screen

IT has announced SAP S/4HANA for December 2026. The design of the Planner and the KPIs does not change; what can change is how much the tool keeps. The rule stays the same: whatever the new system can hold and export is done in SAP, and the tool covers only the rest.

The questions we would ask

Only what the weekly process needs from the system as users: which screens, which columns, which history. Questions 1 and 2 matter before December; 3 to 5 can wait until the new system is configured.

  1. Will the Equipment Manager menu keep the reports we export each week, or their equivalents, with export to Excel? before DecemberMaintenance Backlog Report (ZEMR031), Display Working Times (CATS_DA), Mechanical Time Entry (ZEME047).Every maintenance KPI comes from these three exports: which orders exist, their planned hours, and the hours each person booked to each order on each day. If one changes name or screen, we want to know the new one so the weekly process does not stop.
  2. Will closed orders and the hours booked before the change still be readable and exportable afterwards? before DecemberTrends compare weeks, and several indicators are computed on the orders closed in the week. If the history stays in the old system only, we export it before the change.
  3. In the new system, could the order list we export include the scheduled start date and the order's status?The compliance indicators compare what was committed for the week with what was executed. Today no export shows it, so the commitment is recorded in the tool. If the new list shows it, the commitment can live in SAP.
  4. Will the Maintenance Scheduling Board be available to our role?It records which orders are scheduled for which day inside SAP, which is what question 3 is about. If it is not planned, the answer to question 3 is enough.
  5. Will there be a read-only path, such as OData, for orders and working times?Today the files are exported and uploaded by hand each week. Read-only access would remove that step. Not urgent, and nothing is written to SAP.

What we do on our side before December

  • Freeze and KPI history in the tool from the first week, so the history exists when the new system arrives.
  • Data entered in standard fields, which carries over in any case: the committed day as the order's basic start date, hours entered with the real date and the order, orders completed (TECO) when finished, work values on the preventive task lists.
  • Export the full history before the change: all closed CMT1 orders and as many weeks of working times as the report allows, whatever the answer to question 2.
